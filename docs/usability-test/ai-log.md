# AI協作日誌

每週記錄 3 到 5 筆。最有價值的紀錄是「AI的產出不符合使用者需求，你發現並修正」的經驗。第三週發表時，會從這裡挑一個例子說明。

## 第一週

### 1. 整理三類角色訪談紀錄與跨受訪者矛盾需求決策

- **我的提示**：請依使用者角色分別整理訪談記錄，列出各自的需求與痛點，並標出不同受訪者之間矛盾的地方、同一位受訪者前後改變想法的地方，以及訪談中沒說清楚的地方；接著依我拍板的決定（預設按儲存／認證才跳下一筆，但另供快速帶入正常片語並完成跳下一筆按鈕；儲存與認證並存；預設隱藏已 DC 與未照但提供顯示與計入開關）製作單頁 HTML 互動雛型。
- **AI 的產出（摘要）**：AI 依報告醫師、放射師、超音波技術員整理出痛點與三組核心矛盾，並依案例模擬資料產出第一版單頁互動雛型（含工作清單統計看板與打報告雙欄畫面）。
- **我的判斷或修正**：AI 初版為了強調有滿足所有訪談設計決策，在畫面上塞入了大量解釋性文字（例如「報告醫師專用介面 (UI 已與放射師端區隔)」、「預設登入醫師甲」、「直接呈現免進選單」與底部長篇「連續打報告跳轉規則」），這些屬於「給評分者看的設計說明」而非「真實使用者需要的介面元素」。我決定逐步刪除這些教學式贅字，保留真正的控制開關與互動邏輯。

### 2. 建立報告醫師人物誌（Persona）與現行任務流程痛點圖

- **我的提示**：請依訪談為報告醫師建立人物誌草稿，只使用訪談中有依據的資訊，推測的部分請明確標示。接著畫出醫師從開啟工作清單到完成一份報告的任務流程（Mermaid 格式），並標出現行系統的痛點發生在哪些步驟。
- **AI 的產出（摘要）**：AI 嚴格區分【來自訪談】與【推論與推測】建立報告醫師人物誌，並繪製出從「開啟工作清單 → 清點未完成數量 → 點選檢查單 → 手動調閱 PACS 與歷史報告 → 點選片語與打字 → 儲存／認證 → 返回清單找下一筆」的 Mermaid 流程圖，標出 7 個現行痛點節點。
- **我的判斷或修正**：透過流程圖清楚確認了現行系統最大的時間浪費在於「每次都要手動點調閱影像」以及「打完一份要退回清單重找下一筆」，因此要求雛型必須在點選檢查單時自動載入影像，並在儲存／認證後自動跳轉至下一筆未完成報告。

### 3. 首頁「未完成報告統計」與「搜尋篩選／工作清單」之資訊密度修正

- **我的提示**：把待打報告的 card 縮小、標題改為「未完成報告統計」、刪掉單位「份」並濃縮成一行；把查詢欄位精簡並將「清除篩選條件」放入第一行；將「顯示: 醫令已DC / 未照影像」與「底色與狀態說明」移至「檢查工作清單」標題同一行，最後將查詢卡片與工作清單卡片合併。
- **AI 的產出（摘要）**：AI 一開始生成的統計看板採用了大字級（`32px`）與雙行卡片，加上獨立的搜尋面板與下方的特殊單據設定列，佔掉了首頁近一半的垂直高度，導致最重要的工作清單表格被擠到畫面下半部。
- **我的判斷或修正**：我發現報告醫師每天要看大量清單，首頁上方控制區絕對不能佔用過多垂直空間。因此我要求 AI 將統計看板、搜尋列、工作清單標題列全部改為**單行不換行**，並將搜尋列與工作清單合併進同一張卡片（`.table-card`），大幅提升了首頁第一眼可見的檢查單筆數。

## 第二週

至少包含一項「AI的評估你不同意」的例子與理由。

### 1. 從參考視覺圖提取 Design Tokens（`tokens.css`）並建立專案 Skill（`SKILL.md`）

- **我的提示**：請根據 `tokens.css` 的格式，把 `p-interest web example.jpg` 的元素更新 `tokens.css`，接著做成 Skill 並生成 `SKILL.md`，再依照新建立的 Skill 更新 `index-test.html`。
- **AI 的產出（摘要）**：AI 從參考圖片提取出深炭黑（`#111111`）、暖米白（`#F7F3EF`）與四色高明度粉彩（暖黃 `#FFE59A`、櫻花粉 `#FFB5C1`、薄荷綠 `#B7E1D1`、天空藍 `#A9D3FF`），建立 `tokens.css` 與 `.agents/skills/design-system/SKILL.md`，並將雛型更新為膠囊按鈕與粉彩狀態標籤風格。
- **我的判斷或修正**：AI 初次套用四色粉彩時，只給了「未完成、已完成、已認證、已DC」四種狀態顏色，卻讓表格中的「`📷 已照`」與「`⏳ 未照`」都使用相近的灰米色，且上方圖例的「未照」誤用了相機圖示 `📷`（與表格內的 `⏳ 未照` 不一致）。我不同意這種不一致且缺乏區辨度的配色，因此要求 AI 將圖例的未照圖示改為漏斗 `⏳`、新增「`📷 已照`」與「`⚠️ 未指派`」專屬底色、對調已照（淺暖灰常態色）與未照（薰衣草紫警示色）的底色，並直接將底色套用在狀態圖示與文字上，依「醫令狀態 → 影像狀態 → 報告狀態 → 未指派」順序排列。

### 2. 工作清單預設降冪排序後，打報告頁「上一筆／下一筆」無反應之修正

- **我的提示**：把檢查工作清單表格的「檢查日期時間」欄位預設以降冪排序；接著我測試時發現在打報告頁面中，點上一筆、下一筆時，畫面沒有反應。
- **AI 的產出（摘要）**：AI 將工作清單的 `sortAsc` 設為 `false`（降冪），但打報告頁面的佇列函式 `getNavigableQueue()` 與 `findNextPendingExam()` 仍維持原始陣列順序，且頂部顯示的「⬅️ 上一筆：... / ➡️ 下一筆：...」膠囊只是純文字 `<span>` 而非可點擊按鈕。
- **我的判斷或修正**：當我從工作清單點進第一筆（最新日期的 `R0008`）時，因為 AI 在打報告佇列中沒有同步套用工作清單的排序方向，`R0008` 被當成最後一筆，導致「下一筆」變成停用狀態，且點擊頂部的上下筆膠囊也毫無反應。我指出此問題後，AI 才將打報告佇列與工作清單的排序邏輯同步，並把頂部的上下筆膠囊改為可點擊的 `<button>`，同時設定 `max-width` 省略號避免因為檢查名稱長短而換行。

## 第三週

### 1. 將 PACS 影像操作（全螢幕、調整順序、播放、歷史影像預覽）由「示意」改為真實功能

- **我的提示**：請把打報告畫面中 PACS 影像顯示區下方的「全螢幕」、「調整順序」、「播放」做出真實功能，將工具列縮成一行（順序改為：縮小、放大、全螢幕、重置、調整順序、播放、隱藏），並讓「過去影像及報告」也能預覽歷史影像且點第二次可收合。
- **AI 的產出（摘要）**：AI 最初在影像工具列與歷史報告預覽中，有部分按鈕僅彈出 Toast 提示「示意功能」，且影像畫布內部下方與外部下方重複放置了兩組縮放與全螢幕按鈕。
- **我的判斷或修正**：為了讓第三週可用性測試時受測者能真實操作，我要求移除影像畫面內部下方重複的控制按鈕、將資訊視窗移至右上角，並實作出真正的 4 切面序列拖曳／按鈕調序（`↕️ 調整順序`）、動態心臟搏動與切面循環播放（`▶️ 播放`），以及歷史影像縮圖預覽與主畫面並排對照功能，同時支援再次點擊同一筆歷史紀錄即可收合預覽視窗。

### 2. 打報告主卡片整合、按鈕色彩映射與空間穩定度修正

- **我的提示**：把底部操作列按鈕精簡為同一行，「帶入正常片語並完成」改為「帶入正常片語並儲存」，並把「儲存」按鈕改成與「已完成」相同的藍色底；接著把病人資訊、影像系統、過去影像及報告、打報告卡片放在同一張卡片裡，且點選預覽時打報告下方的按鈕位置不要跟著跑掉。
- **AI 的產出（摘要）**：AI 將四個區塊合併進 `.report-main-card` 時，起初在右側 `.editor-panel` 使用了 `justify-content: space-between`，導致當左側點開「過去影像及報告」預覽視窗使左欄變高時，右側底部的「儲存／認證」按鈕列跟著被往下推。
- **我的判斷或修正**：我立即發現左側展開預覽時右側按鈕位置跑掉，這會嚴重干擾醫師連續點擊「儲存／認證」的肌肉記憶；修正為 `justify-content: flex-start` 後，右側操作列便穩定錨定在報告欄位正下方。此外，我也將「`💾 儲存`」按鈕從原本的黑色底改為與「`💾 已完成`」狀態一致的天空藍底（`#A9D3FF`），讓「儲存（藍色）→ 已完成（藍色）」與「認證（綠色）→ 已認證（綠色）」具備完全一致的視覺回饋。
